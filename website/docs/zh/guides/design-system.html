指南

设计系统

视觉层是一个没有任何业务依赖的独立包，所以它可以整体交给设计团队维护，业务团队直接消费，两边不互相改代码。

分层

@mvp/design-tokens    原始比例 -> CSS 自定义属性
@mvp/design-system    语义 token、主题、Tailwind preset、基础 reset
@mvp/ui               7 个组件（Button、Card、Image、Section、Skeleton、AppNav、
                      ProductCardBase）+ ./shadcn（11 个原语）
fragments/*           消费 @mvp/ui 和 CSS 变量；绝不重新定义 token

分层规则是被强制的：dependency-audit.json 带 tags 和 depConstraints（仿 @nx/enforce-module-boundaries），违规是 layer-constraint-violation。片段可以 import @mvp/ui；@mvp/ui 不能 import 片段、页面或 domain 包。

设计与业务之间的契约

跨越边界的一切都是 CSS 自定义属性，前缀 --mvp-：

import { tokens, cssVariableNames, TOKEN_PREFIX } from "@mvp/design-system";
// TOKEN_PREFIX === "mvp"   ->   --mvp-color-…, --mvp-radius-sm, …

cssVariableNames 是系统输出的全部变量的冻结清单。正是这份清单让边界可审计：audit:css 把没人引用的选择器或变量算作无用字节，所以设计团队删掉的 token 不可能悄悄残留。

业务代码通过设置变量来调整外观，而不是去改组件：

.trade-terminal { --trade-panel-bg: var(--mvp-color-surface-sunken); }

片段已经在遵循这个约定 —— order-book 的样式表读 var(--trade-panel-border, #23262f)，即「业务作用域变量 + 字面量兜底」，主题层缺席时面板照样渲染。

主题

import {
  createThemeVariables, createAllThemeVariables, createBaseVariables,
  emitDeclarations, DARK_MODE_SELECTOR, themeColors,
} from "@mvp/design-system";

两套主题（ThemeName = "light" | "dark"），按属性切换：DARK_MODE_SELECTOR === '[data-theme="dark"]'。Tailwind preset 配成 darkMode: ["selector", DARK_MODE_SELECTOR]，所以 Tailwind 的 dark: 变体和原始 CSS 变量认的是同一个开关。

主题同时也是一个请求上下文维度（ctx.theme：light | dark | system），网关提供 GET /_shell/theme，所以这个选择能扛过整页刷新，而不是只活在客户端状态里。

Tailwind

// 消费方的 tailwind.config.ts
import { tailwindPreset } from "@mvp/design-system";
export default { presets: [tailwindPreset], content: ["./src/**/*.{ts,tsx}"] };

preset 把 Tailwind 的 theme key 映射到 var(--mvp-…) 而不是复制值，所以每个 token 只有一处定义。@mvp/ui 另外发布 ./tailwind.config 和 ./shadcn/globals.css 供直接使用。

组件元数据

每个 @mvp/ui 组件都在组件旁边带 metadata.ts（category、serverSafe、propsSchema、description）、budget.ts 和 fixtures.ts。fixtures 是相似度审计和组件开发工作台（pnpm dev:component）消费的东西，serverSafe 则是服务端/客户端边界审计要核对的字段。

把这一层交出去

实务上，一个设计团队可以整体拥有 packages/design-tokens、packages/design-system 和 packages/ui 并独立出货，因为：

  • 这三个包不 import 任何 domain 或产品代码（被强制）；
  • 它们的公开面就是 token + 组件 + 一个 Tailwind preset；
  • audit:css 和 audit:similarity 恰好守住共享 UI 层真正会踩的两个坑 —— 死 CSS，以及「新加一个近似重复的组件而不是复用已有的」。

没有被自动化的是视觉回归。仓库里没有截图基线，所以一个改变布局的 token 变更，只有在恰好有 Playwright 跑过时才可能被 maxCLS 抓到 —— 而 web vitals 检查并不属于 pnpm verify（F11）。
