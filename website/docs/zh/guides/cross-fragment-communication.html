跨片段通信

独立部署的片段之间仍然要说话：在盘口点一个价格，得把下单表单填上。这件事在 Podium 是明确不管的；在这里它是一份契约。

契约

每个频道声明一个发布者、一份显式订阅者名单和一份 Zod 载荷 schema：

// domains/trade-contracts/src/slices.ts
export const tradeSliceContracts = [
  {
    channel: TRADE_ORDER_DRAFT_PRICE,      // "trade.order-draft.price"
    publisher: "order-book",
    subscribers: ["order-form"],
    payloadSchema: orderDraftPriceSchema,
  },
  // …
] as const;

交易 demo 声明了 7 个频道：

频道发布者订阅者
trade.active-symbolsymbol-switcherchart-panel、order-book、trades-feed、order-form、market-header、positions-table、account-bar
trade.order-draft.priceorder-bookorder-form
trade.order-draftorder-formorder-form、order-preview
trade.chart-intervalchart-panelchart-panel
trade.hovered-priceorder-bookorder-form、chart-panel
trade.book-groupingorder-bookorder-book
trade.leverageaccount-baraccount-bar、order-form

发布者和订阅者 id 是逻辑组件 id，不是片段名。symbol-switcher 是页面使用的 owner 身份（apps/page-trade/src/hydrate.tsx），不是 fragments/ 下的某个服务。这是这里最常见的接入错误。

publisher 是单数：一个频道恰好一个。如果两个组件都要发布同一个概念，那要么是两个频道，要么是一个共享的 owner 身份 —— 不是一个列表。

使用总线

import { createInteractionBus, validateInteractionPayload } from "@mvp/interaction";

const bus = createInteractionBus({ contracts: tradeSliceContracts });

const off = bus.subscribe(TRADE_ORDER_DRAFT_PRICE, (payload) => setPrice(payload.price), {
  owner: "order-form",
});

bus.publish(TRADE_ORDER_DRAFT_PRICE, { price: 64000 }, { owner: "order-book" });

未声明的发布、或来自非契约指定发布者的发布，在运行时抛 InteractionContractError。载荷按 payloadSchema 校验。

createBroadcastBridge 把总线经 BroadcastChannel 扩展到跨浏览器标签页。

Mutation

会打到后端的状态变更被显式建模，而不是当作「发了就不管」的事件：

import { defineMutation } from "@mvp/interaction";
const placeOrder = defineMutation({ /* input/output schema + execute */ });

契约违规抛 MutationContractError。下单表单的流程展示了这个模式：在 placeOrder.execute 运行之前，先拿品种约束校验订单，所以一个非法订单永远到不了撮合引擎。

客户端 slice store

import { createSliceStore } from "@mvp/store";

const store = createSliceStore<TradeSlices>(tradeStoreContracts, {
  initial: structuredClone(initialTradeSlices),
  owner: TRADE_STORE_OWNER,
});

store.get(TRADE_ACTIVE_SYMBOL);
store.set(TRADE_ACTIVE_SYMBOL, { symbol: "ETH" });
store.subscribe(TRADE_ACTIVE_SYMBOL, (payload) => { /* … */ });

useStoreSlice 是 React 绑定。频道与 slice key 天然对齐：slice 名就是频道的主题尾段。

store 是客户端机制，契约才是事实来源。同一份名单有两种形状正是因此 —— tradeSliceContracts（岛屿级、规范）与 tradeStoreContracts（为通用 store 的类型参数重排）。

没有被校验的东西

没有任何机制校验「声明的发布者/订阅者 id 是否对应一个真实存在的组件」。order-preview 作为订阅者出现，而它在仓库里别处都不存在（F13）。
