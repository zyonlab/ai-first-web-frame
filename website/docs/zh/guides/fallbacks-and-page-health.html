降级与页面健康

局部降级是设计出来的特性。这一篇回答的问题是：降级在什么时候会改变 HTTP 状态码？

三个层级

层级含义
槽位降级某个槽位渲染它在 manifest.fallback 里声明的 HTML
degraded至少一个可选槽位降级了 —— 页面仍返回 200
unhealthy至少一个必需槽位降级了 —— 网关返回 503

槽位上的 required: true 是把失败从「影响观感」升格为「致命」的开关。这就是 Tailor 的 primary 语义：一个主内容已死的页面不该回 200，否则爬虫会把降级标记当成真实内容收录，成功率监控也什么都看不到。

状态码到底是怎么被设置的

Next.js App Router 的 page.tsx 无法设置响应状态或头 —— 只有 middleware 和 route handler 可以。但网关本来就把上游主体当文本读。所以页面把健康状况盖进标记里，由网关翻译：

import { PageHealthMeta } from "@mvp/runtime/react";

<PageHealthMeta health={execution.health} failed={failedRequiredSlotNames(execution)} />

输出：

<div hidden data-mvp-page-health="unhealthy" data-failed-slots="book,orderForm"></div>

（即 @mvp/runtime 里的 PAGE_HEALTH_ATTR 和 PAGE_HEALTH_FAILED_ATTR —— 注意第二个是 data-failed-slots，不是 data-mvp- 前缀。）

网关调用 readPageHealthFromHtml，在 unhealthy 时返回 503 + retry-after，同时原样返回主体。degraded 保持 200。

SHELL_REQUIRED_FAILURE_STATUS=0 关闭这层翻译，保留上游状态码。

为什么是隐藏的 div 而不是 <meta>

因为这是给网关的内部信号，不是关于文档的元数据。React 19 确实会把页面组件里渲染的 <meta> 提升进 <head>（已由 SSR 探针实测），而 <head> 是文档对外的元数据面，会被爬虫和第三方工具读取。一个降级信号不该出现在那里。

在 React 18 下，同样的 <meta> 会留在 <body> 里，那是无效 HTML。仓库现在用 React 19，所以这个约束已经消失 —— 保留隐藏 div 从「被迫的变通」变成了「刻意的选择」。

流式页面

用 PageHealthMetaStream，它接收聚合 promise，在汇总结果已知时输出标记。标记必然出现在主体靠后的位置 —— 这没问题，因为网关本来就要缓冲页面主体才能翻译状态码。

怎样设计一个好的降级内容

  • 保留 data-fragment="<name>" 根节点，并加上 data-fallback="true"。运行时代码认这个属性：实时面板驱动拒绝在降级节点上挂载。
  • 在没有 JavaScript 的情况下也能读。no-js 这个 Playwright project 会在禁用 JS 的情况下渲染每个页面并断言内容还在。
  • 不要留零高度。maxCLS 的预算是 0，一个先塌陷再撑开的降级内容就是一次布局偏移。
