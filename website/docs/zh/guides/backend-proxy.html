指南

后端代理

已水合的岛屿用来访问自己那个后端的通道：同源、无 CORS，且片段的真实服务地址永不到达浏览器。

问题

片段在 SSR 期间能访问自己的后端 —— 它是一个服务，它有 @mvp/request。它水合后的岛屿不能：浏览器只知道公共源站，而片段的 serviceUrl 是内网地址（而且必须保持在内网）。在这层存在之前，根本没有标准通道。

声明一个

在片段的 src/manifest.ts 里：

proxy: {
  account: "/account",                          // 相对：相对本片段的 serviceUrl 解析
  rates:   "https://rates.internal.example/v2", // 绝对：共享的或第三方后端
}

FragmentManifestSchema.proxy 接受绝对 http(s) URL 或根相对路径。相对形式是对 @podium/proxy 的刻意偏离：片段自己的端点在每个环境里都在不同主机上，绝对的自指目标就必须把环境变量插值进一份静态 manifest。

网关挂载成什么

/_fragment/<fragment>/<target>/*   →   <解析出的 base>/*

于是岛屿在页面自己的源站上调用 /_fragment/order-form/account。同源、无 CORS，真实服务地址不外泄。

所有 HTTP 方法都会被转发（server.all）。请求体原样转发而不是重新序列化成 JSON —— 早期版本做的是 JSON.stringify(request.body ?? {})，会破坏文本和表单请求体。

声明的 base 就是边界

纯解析逻辑在 packages/runtime/src/fragmentProxy.ts：

parseFragmentProxyPath(pathname)       // -> {fragment, target, rest} | null
buildFragmentProxyUrl(base, rest, search, serviceUrl)
resolveFragmentProxy(options)          // 整个决策

会逃出声明 base 的余项被拒绝，而不是被规范化掉。一个目标只有在 manifest 里声明过才可达。

一个值得知道的细节（如果你要直接用这些函数）：空余项不能补出一个尾斜杠。Fastify 把 /account 和 /account/ 当作两条不同的路由，所以 /_fragment/order-form/account 和 /_fragment/order-form/account/ 是两个不同的请求，而只有其中一个是你声明的那个。

超时：SHELL_FRAGMENT_PROXY_TIMEOUT_MS。
