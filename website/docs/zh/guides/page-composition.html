页面组合

页面声明槽位，框架去填。页面里绝不出现按片段写的接线代码。

manifest 是唯一事实

apps/<page>/src/manifest.slots.json 是一个 JSON 数组（不是 {slots: [...]}）：

[
  {
    "name": "promotion",
    "fragment": "promotion-banner",
    "channel": "stable",
    "strategy": "cached-ssr",
    "timeoutMs": 200,
    "props": { "scene": "home", "campaignId": "summer" },
    "cachePolicy": { "ttl": 60, "tags": ["promotion", "home"], "vary": ["tenant", "locale"] },
    "required": false
  }
]

用 mount-slot 改它，不要手编辑 —— 一次成功的挂载会从它重新生成 src/fragmentSlots.gen.ts，而 pnpm verify:manifest-gen 在两者漂移时判失败。

src/fragmentSlots.ts 仍然手写，但很薄：它包装生成的数组，只添加静态表达不了的按请求粘合逻辑 —— timeoutMs 覆盖、resolveData 函数，或（page-trade 上）合并按请求变化的 props.symbol。

渲染槽位

import { FragmentSlot, PageHealthMeta } from "@mvp/runtime/react";

const execution = await executeFragmentSlots({ slots, registry, ctx, dataDependencies });

return (
  <main>
    <FragmentSlot result={execution.slots.promotion} />
    <PageHealthMeta health={execution.health} failed={failedRequiredSlotNames(execution)} />
  </main>
);

executeFragmentSlots

一道屏障：全部解析完，你再渲染。简单。

streamFragmentSlots

立即返回，每个槽位一个 promise 加一个聚合 promise，外壳和每个 <Suspense> 边界可以在自己那层结束时就 flush。

前者其实就是 streamFragmentSlots(options).result。

四种渲染策略

策略行为
static不调用服务；输出 manifest 里的 staticHtml
ttl-cache在新鲜期内从有界的进程内缓存返回
cached-ssr渲染后按 cachePolicy 缓存
dynamic-ssr每请求渲染

cachePolicy.vary 用上下文维度（tenant、locale、props）切分缓存键。缓存是有界的（DEFAULT_FRAGMENT_CACHE_MAX_ENTRIES），配有 pruneFragmentCache 和基于标签的 invalidateFragmentCacheByTag。

每个槽位结果都可检视

type FragmentSlotResult = {
  slot: FragmentSlotDefinition;
  strategy: RenderStrategy;
  source: "static" | "cache" | "network" | "fallback";
  status: "ok" | "fallback" | "skipped-dependency";
  // …
};

source 回答「这些字节从哪来」；status 回答「它成功了吗」。一个槽位可以是 source: "fallback" 且 status: "fallback"（它自己的服务挂了），也可以是 status: "skipped-dependency"（它依赖的东西先挂了，于是它根本没被尝试）。
