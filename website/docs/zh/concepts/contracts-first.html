契约优先

packages/contracts/src/index.ts 导出 35 份 Zod schema，外加 6 份预生成的 JSON Schema。系统里每一条边界都是其中之一。

DataFreshness × DataPrivacy 这张网格决定了一份数据可以被缓存在哪里、缓存多久。user-private 的数据绝不能落进共享缓存条目 —— 这正是 cachePolicy.vary 存在的原因，也是 @mvp/storage 有 requiredPartitionKeysForPrivacy 和 assertStoragePolicy 的原因。

给非 TypeScript 消费方

import { toJsonSchema, FragmentManifestJsonSchema } from "@mvp/contracts";
toJsonSchema(SomeSchema, "SomeSchema");   // draft-07，可选 $ref 包装

6 份 schema 预生成发布，好让只会 JSON Schema 的工具能校验 TypeScript 消费方经 z.infer 得到的同一套契约：片段 manifest、页面 manifest、片段注册表、渲染请求、渲染响应、请求上下文。

在边界处解析

import { parseFragmentRenderRequest, parseFragmentRenderResponse } from "@mvp/contracts";

const parsed = parseFragmentRenderRequest(body);
// { ok: true, request, strict: boolean } | { ok: false, issues }

parseFragmentRenderRequest 是刻意两层的：先严格 schema，再一个 ctx 为 .partial().optional() 的信封，两者都失败才 400。strict 告诉调用方命中了哪一层 —— 而这个信号目前在任何地方都被生产出来又被丢弃（F14）。

预算也是契约

import { loadDefaultBudget, mergeBudget, assertBudget, createBudgetReport } from "@mvp/contracts";

assertBudget 在违规时抛错；createBudgetReport 返回结构化对比。注意：schema 里有这个字段，不代表有闸门在读它 —— 见性能预算。

哪些地方刻意不用 schema

  1. 业务词汇。不要加宽 RequestContextSchema，用 ctx.extensions。
  2. 交互载荷。那些 schema 住在 domain 层（domains/trade-contracts/src/slices.ts），和频道 id 挨着，而不在 @mvp/contracts —— 框架只提供 InteractionContractSchema 规定「一份契约该长什么样」，具体契约由 domain 提供。
