AI 接入

这是唯一一条没有框架级竞品的能力轴，所以值得具体说清楚存在什么，而不是泛泛地说「对 AI 友好」。

四个机制

1 · 仓库根部一份操作手册

CLAUDE.md 是 agent 的入口：硬规则、目录地图、带每步验收标准的片段生命周期、常用命令，以及一张按脚本实际打印的字符串索引的失败恢复表。AGENTS.md 是它的符号链接，所以两者不可能漂移。

2 · 每个包一份 AGENT.md，且被 CI 执行

每个 packages/* 和 domains/* 目录都带一份 AGENT.md，含入口点小节、可用示例和验收块。其中的 ts/tsx 代码块会被 pnpm docs:test 运行，而它是 pnpm verify 14 道闸门之一。

pnpm docs:test        # 36 份 AGENT.md，41 个可执行块，7 个标记为 no-run

需要示意而非运行的块标记为 ```ts no-run，报告单独计数（noRunBlocks）—— 所以「我们跳过了它」是可见的，而不是静默的。一个不再编译或不再断言的示例就是一次红色构建。

这是让其余一切可信的机制。agent 读到的文档，是 CI 刚刚证明过还能跑的文档。

3 · 八个 MCP 工具

pnpm mcp 启动服务（packages/mcp/src/server.ts）。

工具包装的是
scaffold_component@mvp/create-component
register_fragmentscripts/register-fragment.mts
mount_slotscripts/mount-slot.mts（含 --remove / --check）
promote_fragmentscripts/promote-fragment.mts
rollback_fragmentscripts/rollback-fragment.mts
affectedaffected 计划图引擎
query_registry单元依赖图
affected_units给定变更单元 id，返回需重新验证的闭包

前六个直接委托给人类也在用的同一批 CLI，所以只有一份实现、一套语义 —— 工具的行为不可能偏离被记录的命令，只有它的描述可能，而那正是 F12 曾经发生过的事。

packages/mcp/src/validate.ts 另提供 findSchemaViolation，用于拿导出的契约校验一份载荷。

4 · 结构化的 CLI 输出与带类型的失败

每个生命周期 CLI 打印带 status 的 JSON，且状态词表是封闭的：

脚本状态
register-fragmentregistered · conflict · failed
mount-slotmounted · conflict · failed
promote-fragmentpromoted · unchanged · conflict · failed
rollback-fragmentrolled-back · unchanged · conflict · failed
verify-manifest-genfresh · stale · exempt · failed
verify-unitok · passed · skipped · failed

未知 flag 会被拒绝而不是忽略：每个脚本把自己的白名单交给 unknownFlagError，后者返回带 did you mean --<flag>? 的建议。像 --chanel canary 这样的拼写错误，以前会被静默丢弃、脚本按默认值继续；现在是 {"status":"failed"} 且不写文件。

全部审计规则码见诊断码。

推荐的 agent 循环

  1. 读 CLAUDE.md，再读你要改的那个包的 AGENT.md。
  2. 动手改。
  3. pnpm --filter <pkg> test 走紧循环。
  4. 宣布完成之前跑 pnpm verify，并且读 reports/*.json，不要只看退出码。
  5. 如果改的是片段，再跑一次 pnpm verify:unit --name <fragment>。

目前仍会浪费 agent 时间的地方

如实记录，因为这些正是 agent 现在只能靠猜的地方：

  • 有两个 flag 只存在于代码里，手册没写（F4）。
  • 建议性的优化器报告里，19 个槽位中有 10 个带着确信但错误的建议（F1）—— agent 照 recommendation 执行会把实时面板搞坏。
  • 仓库根的 reports/ 和 docs/reports/ 是两样东西，名字却很像。
  • 没有任何测试比对「文档里写的文件数」和「脚手架实际产出」，所以这类漂移会再次静默发生（F12）。
