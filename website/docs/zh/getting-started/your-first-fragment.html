上手

第一个片段

完整循环：脚手架 → 实现 → 注册 → 挂载 → 验证 → 晋级。每个命令都打印带 status 字段的 JSON 信封，失败时不写任何文件。

1 · 脚手架

pnpm --filter @mvp/create-component start -- PricePanel --type fragment

输入 PascalCase，产出 fragments/price-panel/，11 个文件：

src/server.ts        src/render.ts       src/manifest.ts   src/budget.ts
src/fixtures.ts      src/render.test.ts  tests/server.test.ts
package.json         tsconfig.json       Dockerfile        README.md

验收："status": "created" 且 files.length === 11。

生成出来的单元直接就能跑：src/server.ts 是 @mvp/fragment-host 上约 20 行的适配器，端口取 4201 之后第一个空闲值，Dockerfile 真的能构建。不要手写片段服务器 —— audit:deps 的 fragment-server-not-hosted 规则会判失败。

--type ui 则产出 packages/ui/src/<Name>/，8 个文件。同一个命令，两种形状。

2 · 先写测试，再实现

$EDITOR fragments/price-panel/src/render.test.ts   # 先扩测试
$EDITOR fragments/price-panel/src/render.ts
pnpm --filter @mvp/fragment-price-panel test

render.ts 收 {props, ctx}，返回 {html, assets, cache, metadata}。标记要自包含：片段的 CSS 随自己的 <style data-fragment-style="..."> 一起出货，且类名必须能从源码里被引用到，否则 audit:css 会把它算成无用字节。

3 · 注册

pnpm exec tsx scripts/register-fragment.mts \
  --name price-panel --version 0.1.0 \
  --service-url http://localhost:4203 \
  --channel canary --with-compose

完整 flag 集（取自脚本自己的白名单，scripts/register-fragment.mts）：

Flag说明
--namekebab-case 片段名
--version该通道应解析到的版本
--service-url必须能解析为 URL
--manifest-url默认 <service-url>/manifest
--assets-url可选；用于岛屿 JS 由别处提供的片段
--channelstable | canary | preview
--portcompose 端口；已被占用的端口会被拒绝
--with-compose同时把服务写进 infra/docker/docker-compose.yml

验收："status": "registered"。原样重跑会打印 "action": "unchanged" —— 脚本是幂等的。

运行时覆盖：PRICE_PANEL_URL=https://… 无需写注册表即可为该片段改写 serviceUrl/manifestUrl。（但它不改写 assetsUrl —— F2。）

4 · 挂载到页面槽位

pnpm exec tsx scripts/mount-slot.mts \
  --page page-home --slot pricePanel --fragment price-panel \
  --strategy dynamic-ssr --channel canary --timeout-ms 200

完整 flag 集：--page --slot --fragment --strategy --channel --timeout-ms --props --static-html --cache-policy --data-dependencies --depends-on --required --remove --check --allow-unregistered

  • --depends-on 让本槽位排在另一个槽位之后；--data-dependencies 指的是页面数据源注册表里的条目。见槽位调度。
  • --required 让本槽位失败时页面变 unhealthy → 网关返回 503。
  • 挂载一个未注册的片段会失败（"status": "failed"，不写文件）。先注册，或用 --allow-unregistered 告警后继续。--remove 不受此限制。

验收："status": "mounted" 且 warnings 为空。

成功的挂载/卸载会同时从 manifest 重新生成 apps/<page>/src/fragmentSlots.gen.ts。不要手改那个文件。mount-slot --page <page> --check 不写任何文件、只校验生成文件是否同步；pnpm verify:manifest-gen 对每个页面都跑一遍，并且是 pnpm verify 的一部分。

5 · 验证

pnpm verify                            # 14 道闸门，整个仓库
pnpm verify:unit --name price-panel    # 该单元能构建、能启动、版本自洽

不要带着失败的审计或预算出货。

6 · 晋级，以及回滚

pnpm exec tsx scripts/promote-fragment.mts --name price-panel
# "status":"promoted"，带 from/to 版本

pnpm exec tsx scripts/rollback-fragment.mts --name price-panel [--to 0.1.0]
# "status":"rolled-back"

晋级会把上一个 stable 记进该条目的 versions 历史，并追加到 registry/releases.json（只追加）。不带 --to 的回滚恢复到晋级时记录的版本；没有记录目标时干净地失败 —— 从未晋级过的片段就是这种情况。

并发

四个生命周期脚本都以原子方式写入（临时文件 + rename），外加 <file>.lock 咨询锁和乐观内容哈希校验。若另一个进程在你加载之后改过该文件，你会拿到 {"status": "conflict", "retry": true}、exit 1、不写文件。原样重跑即可。
