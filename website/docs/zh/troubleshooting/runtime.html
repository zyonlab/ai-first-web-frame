运行时

某个槽位渲染了降级内容

先读槽位结果，它把不同情况区分开：

statussource含义
fallbackfallback片段自己的渲染失败或超时
skipped-dependencyfallback它依赖的东西先失败了，所以它根本没被尝试
okcache来自进程内缓存，不是网络

然后按顺序排查：

  1. 服务起来了吗？curl localhost:<port>/health。
  2. 注册表能解析出槽位要的那个通道吗？curl -s localhost:4100/manifest/fragments | jq '.fragments["<name>"]' —— 这个端点反映的是应用环境变量覆盖之后的状态，所以它回答「实际会调哪个 URL」。
  3. 那个片段上有这个 channel 吗？指向片段所没有的通道会静默地解析成降级内容 —— 没有构建期检查。14 个片段里有 12 个只有 canary。
  4. 超时？把槽位的 timeoutMs 和片段的真实延迟比一比。

页面返回 503

某个必需槽位失败了。主体仍然是降级后的页面 —— 读标记：

curl -s localhost:4100/trade/BTC | grep -o 'data-mvp-page-health="[^"]*"'
curl -s localhost:4100/trade/BTC | grep -o 'data-failed-slots="[^"]*"'

需要拿回上游状态码时用 SHELL_REQUIRED_FAILURE_STATUS=0 关掉这层翻译。

某个岛屿不水合

这通常是握手在正常工作，不是 bug。装一个 handler 把原因读出来：

configureIslandRuntime({ onSnapshotMismatch: (info) => console.warn(info) });
// {island, expected, actual, reason}
原因怎么修
version-mismatch已部署的片段版本 ≠ 页面注册时期望的版本
contract-hash-mismatch同一版本下载荷契约变了 —— 升版本
invalid-snapshot内联 JSON 不满足 IslandSnapshotSchema
invalid-props快照 props 通不过岛屿的 propsSchema —— 通常是新加了必填 prop，而旧 SSR 输出不带它

给岛屿的 propsSchema 加必填字段，对所有旧片段构建都是破坏性变更。先滚动发布片段，或把字段设为可选并给默认值。

某个实时面板收不到帧

  1. SSR 节点存在吗？有没有带 data-fallback？驱动会刻意跳过降级节点。
  2. 面板在页面的面板数组里吗？
  3. 解析出的 source id 存在吗？resolveSourceTemplate 在缺少被绑定参数时会抛错，而不是去订阅一个含字面量 <symbol> 的 id —— 看到这个错误，说明页面没有提供片段声明的某个参数。
  4. 模板是真实的 source id 吗？apps/page-trade/src/liveContract.test.ts 会让解析不出的模板在构建期失败，能在运行前抓住 book.12.<symbol> 这类拼写错误。

切换币对时行没了

对 order-book 和 trades-feed 而言这是预期行为 —— 它们绑定了 <symbol>，所以会被标记 remounted 并重建。如果 positions-table 也被清空了，说明有人给了它一个带参数的订阅；positions 必须保持无参数，这正是它的行能存活下来的原因。

Trace

每次 /render 开一个 span；traceId 来自 ctx.traceId，没有就生成一个。导出是「发了就不管」的，所以慢的接收端不会阻塞响应。用 TRACE_SAMPLE_RATE 和 @mvp/observability 里的导出器（OTLP JSON、文件、控制台）配置。reports/traces/ 下的 trace 快照正是 audit:optimizer 读取的东西 —— 一份都没有时，它的调度提示就无米下炊。

指标

网关和每个片段都有 GET /metrics，Prometheus 文本格式。HTTP 指标来自 createHttpMetrics；recordWebVital 接受客户端上报的 vitals。

看起来像 bug 的正常现象

  • 你在 <body> 里渲染的 <meta> 出现在了 <head>。React 19 会提升文档元数据。这是预期的。
  • reports/ 在 pnpm verify 之后变了。它是机器产物，每次都重写。手写的那份在 docs/reports/。
  • e2e 结果毫无意义。pnpm build 是不是在 pnpm dev 服务期间跑了？重启栈。
  • pnpm e2e 的浏览器用例全挂在 "Executable doesn't exist"。跑 pnpm exec playwright install chromium。
