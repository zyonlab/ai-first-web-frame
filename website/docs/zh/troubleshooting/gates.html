常见失败

症状怎么办
check 只因格式失败biome 在 check 模式下拒绝自动修复。跑 pnpm exec biome check --write <paths>。
duplicated-package-version同一依赖在工作区某处有两个不同区间 —— 包括同一包的 peerDependencies 与 dependencies 分裂。统一区间；本仓库刻意只允许一个。
server-safe-browser-globalpackages/* 文件碰了浏览器全局对象。如果该模块确实只跑在浏览器，给它 "use client"，并考虑做成独立导出子路径，让服务端 bundle 永远拉不到它 —— @mvp/runtime/live 就是这么做的。不要把包加进白名单来躲规则。
fragment-server-not-hosted片段自建了 Fastify 实例。把 src/server.ts 改写成 createFragmentServer 上的适配器。
layer-constraint-violation修正 import 方向，或故意地修改 dependency-audit.json 里的 depConstraints。加个 tag 逃逸不算修复。
raw-fetch-in-business-code改用 @mvp/request 或 @mvp/data。
预算失败缩小客户端入口、把工作移到 SSR，或拆分片段。调大数字是一个决定，应写进提交信息。
相似度失败复用被标出的那个组件，而不是新增一个近似重复的。
verify:manifest-gen 报 stale对该页面重跑 mount-slot（哪怕只是 --check 也会告诉你是哪一页）。生成文件是派生物，JSON manifest 才是源。
docs:test 失败某个 AGENT.md 示例跑不动了。修示例或修代码 —— 不要为了消音把块标成 no-run，除非它确实无法执行，因为报告会统计被跳过的块，而这个数字是要维持在零的。
你没碰过的包 typecheck 失败报告这个既存失败；不要为了变绿去改别的包。

冷克隆

pnpm test、pnpm verify:manifest-gen 和 pnpm docs:test 都会先跑 scripts/ensure-workspace-build.mts，它总是委托给 Turborepo，而不是在 dist/ 只要存在时就跳过 —— 一个存在但过期的 dist/ 正是这道检查要防的失败。如果某道闸门以「找不到某个 @mvp/* 模块」失败，跑 pnpm build 并读构建错误，那才是真正的错误。

题外话但值得知道：14 道闸门是严格顺序执行的（scripts/verify.mts 用 spawnSync 的 map），6 个互不相干的审计并不会重叠。这是延迟问题而非正确性问题（热缓存约 32 秒），但足以解释为什么它不会更快（F9）。
