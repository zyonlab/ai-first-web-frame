诊断码

机器可读的规则码与状态词表，好让 agent（或一段 CI 脚本）能对某一种具体失败作出反应，而不是去 grep 日志。

audit:deps — 14 条规则码

除非注明，严重度均为 fail。报告：reports/dependency-report.json。

规则码含义
layer-constraint-violationimport 跨越了 dependency-audit.json 里的 depConstraints 边界
domain-code-in-framework-packagepackages/* 文件里出现业务词汇
page-importing-another-page一个页面应用 import 了另一个的代码
cross-page-import任何跨页面的伸手
fragment-importing-page-code片段 import 了页面代码，破坏独立部署
fragment-server-not-hosted片段自建 Fastify 服务器而不用 @mvp/fragment-host
raw-fetch-in-business-code裸 fetch(...)；应使用 @mvp/request / @mvp/data
fetch-without-timeout完全没有中止路径的 fetch
server-safe-browser-globalpackages/* 文件在无 "use client" 时碰了浏览器全局对象
client-only-dependency-in-server服务端文件 import 了仅客户端模块
island-bus-without-escape-hatch岛屿接上总线却没有非 JS 路径
duplicated-package-version同一依赖在工作区内被声明成两个不同区间
forbidden-package命中禁用清单的包
large-package依赖超过体积配额

audit:boundary — 4 条规则码

规则码严重度含义
server-imports-client-modulefail服务端文件拉进 "use client" 模块
server-browser-globalfail服务端文件碰浏览器全局对象
page-use-clientfail页面组件被不必要地标为 "use client"
large-client-componentwarn客户端组件超过体积参考线

warn 不会让闸门失败。目前有 4 条 large-client-component 处于未处理状态（F10）。

另外四个审计

它们不使用规则码，各有各的报告形状。

审计报告形状
audit:bundlebundle-report.json{tool, status, checks[], unmeasured[], notes[]}
audit:csscss-report.json{tool, status, metrics{}, budget, checks, findings}
audit:similaritysimilarity-report.json{tool, status, threshold, checkedFiles, matches}
audit:optimizeroptimization-findings.json{tool, status, findings[], traces{}}

bundle 报告里的 unmeasured 数组值得一读：它逐条列出没有被检查的预算字段和原因 —— 这是你发现「某个声明的上限其实不是闸门」的方式。

优化器发现

仅供参考：status 只由 critical 级别的发现驱动，所以 info/low 永远不会让构建失败。

不要不加核实就照 recommendation 执行。当前 19 个槽位的发现里有 10 条是错的 —— 见 F1。
