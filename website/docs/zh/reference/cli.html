命令行

下面的 flag 清单取自各脚本自己的白名单（unknownFlagError），不是散文描述。未知 flag 会被拒绝，并给出 did you mean --<flag>? 建议、{"status":"failed"}、exit 1、不写文件。

生命周期

register-fragment

pnpm exec tsx scripts/register-fragment.mts --name <kebab> --version <semver> \
  --service-url <url> [--manifest-url <url>] [--assets-url <url>] \
  [--channel stable|canary|preview] [--port <n>] [--with-compose]

状态：registered · conflict · failed。幂等 —— 原样重跑报告 "action": "unchanged"。

mount-slot

pnpm exec tsx scripts/mount-slot.mts --page <page> --slot <name> \
  [--fragment <kebab>] [--strategy static|ttl-cache|cached-ssr|dynamic-ssr] \
  [--channel <channel>] [--timeout-ms <n>] [--props <json>] [--static-html <html>] \
  [--cache-policy <json>] [--data-dependencies <json-array>] [--depends-on <json-array>] \
  [--required] [--remove] [--check] [--allow-unregistered]

状态：mounted · conflict · failed。--remove 卸载。--check 不写文件，只校验 fragmentSlots.gen.ts 是否同步。挂载未注册的片段会失败，除非加 --allow-unregistered。

promote-fragment

pnpm exec tsx scripts/promote-fragment.mts --name <kebab>

状态：promoted · unchanged · conflict · failed。把上一个 stable 记进 versions 并追加到 registry/releases.json。

rollback-fragment

pnpm exec tsx scripts/rollback-fragment.mts --name <kebab> [--to <version>]

状态：rolled-back · unchanged · conflict · failed。没有记录目标时干净地失败。

也有更短的别名 —— pnpm register:fragment、pnpm mount:slot、pnpm promote:fragment、pnpm rollback:fragment，在 -- 之后接同样的 flag。

所有生命周期脚本共享的约定

  • stdout 输出带 status 字段的 JSON 信封。
  • 失败时 exit 1，且不写任何文件。
  • 原子写（临时文件 + rename），外加 <file>.lock 咨询锁和乐观内容哈希校验。遇到并发改动：{"status":"conflict","retry":true} —— 原样重跑即可。
