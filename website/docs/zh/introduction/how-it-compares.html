简介

与竞品对位

与解决重叠问题的项目逐条对位。竞品事实取自它们自己的仓库、文档站和 npm registry 元数据并注明调研日期；我方事实对着本仓库源码核过。

总表

能力轴最接近的项目谁更强为什么
服务端页面组合Podium（@podium/layout）各有胜负Podium 更成熟、经过生产检验；我们的调度器（DAG + 数据依赖 + 每槽位流式）它没有对应物。
片段 HTTP 宿主@podium/podlet他们更强同一职责。Podium 多了多语言 podlet 和多年生产年限。
请求上下文传播@podium/context各有胜负我们维度更多且过 Zod 校验；他们可以注册自定义 parser。我们用 ctx.extensions 达到同一目的。
注册表与发布通道OpenComponents各有胜负OC 是真正的注册表服务，能跨团队分发。我们只是一个 JSON 文件 —— 但带通道、晋级/回滚和原子写冲突重试。
片段后端代理@podium/proxy持平曾经是结构性缺失，现已实现（/_fragment/<fragment>/<target>/*）。
客户端集成与版本协商Module Federation 2.0他们更强MF 能协商并加载匹配版本。我们只能检测失配并拒绝水合。
任务缓存 / affectedNx、Turborepo他们更强Nx 自动推断项目图且有远程缓存。我们用 Turborepo 跑 build/test，外加一个手写的 affected 引擎。
延迟服务端渲染Astro Server Islands各有胜负Astro 零配置但 props 走 URL（2048 字节上限、超限转 POST 且不被缓存）。我们走 POST body 没有这个尴尬，代价是要自己跑一个服务。
构建闸门 / 模块边界@nx/enforce-module-boundaries、size-limit、Lighthouse CI各有胜负我们的规则更贴业务（孤儿总线、裸 fetch、片段自建服务）；Nx 的 tags/depConstraints 表达力更强；LHCI 真的在测我们只声明却没测的 web vitals。
agent 可操作性—我们更强没有框架级竞品。Nx 和 Module Federation 都已加入 AI 文档章节，但都没把面向 agent 的契约做成 CI 闸门。

我们真正不一样的地方

可执行文档就是闸门

pnpm docs:test 抽取每份 AGENT.md 的 TypeScript 代码块并运行它们。36 个文件、41 个可执行块。示例过期是构建失败，不是 issue。Podium、Nx、Module Federation、OpenComponents 都没有这一层。

带 ACL 的契约化交互总线

跨片段通信在 Podium 是明确不管的。这里每个频道声明一个发布者、一份显式订阅者名单和一份 Zod 载荷 schema，未声明的发布在运行时直接抛错。

槽位调度是一张图

dependsOn 加 dataDependencies 产生拓扑分层、每槽位超时、失败向下游传播；流式模式下每个槽位一个 promise，自己那层一结束就 flush。Podium 的 layout 是「注册、取、拼」。

诚实地说，该用他们的场景

需要浏览器侧组合、客户端 bundle 独立发布，或运行时版本协商 → Module Federation。

需要用 .NET / PHP / Java / Go 写片段，发布到被其他仓库消费的共享注册表服务 → OpenComponents。

希望组合层足够无聊且久经考验，且不需要各块之间的依赖图 → Podium。

希望 monorepo 的任务图、远程缓存和代码生成器是别人的问题 → Nx。

调研出处

竞品能力于 2026-09-19 从各项目自己的仓库、文档站与 npm registry 元数据核实（@podium/layout 5.4.8、oc 0.50.64、Module Federation 2.0 配置参考、Nx 的 run-tasks 与 enforce-module-boundaries、Astro Server Islands 指南）。竞品的文档目录结构于 2026-09-20 再次核实，来源为 podium-lib/podium-lib.github.io/docs、module-federation/core/apps/website-new/docs/en 与 nrwl/nx/astro-docs/src/content/docs；本套文档的结构正是取这三家的交集。

两件没能核实、因此不作断言的事：Podium 是否有任何通道/金丝雀概念；OpenComponents 注册表是否支持发布通道。两者看起来都不存在，但「文档里搜不到」不等于「不存在」。

值得知道的背景。Zalando 的 Tailor —— 最接近的历史亲缘，也是我们「主片段决定状态码」这一设计（即页面健康）的来源 —— 已于 2022-12-05 归档，README 里没有推荐继任者。这条路有人走到过尽头。
