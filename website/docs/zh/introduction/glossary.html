简介

术语表

按代码里的用法给出定义。凡是两个词容易混淆的，都把区别写明 —— 这套系统里大部分接入错误，本质上是词汇错误。

翻译约定。技术标识符一律保留英文：它们是你要在终端里敲、在 JSON 里写的字符串。dependsOn 就是 dependsOn，不是「依赖于」。

组成单位

术语含义
Fragment（片段）可独立部署的 SSR 服务，对 POST /render 返回 HTML。位于 fragments/<kebab-name>/，跑在 @mvp/fragment-host 上，拥有一个 Dockerfile 和一个端口。现有 14 个。
Page（页面）Next.js App Router 应用（apps/page-*），声明槽位并组合片段。现有 7 个，其中 5 个至少组合了一个槽位。
Shell gateway（网关）唯一的对外源站（:4100）。解析路由、代理到页面应用、挂载片段后端代理、提供 robots.txt / sitemap.xml，并把页面健康标记翻译成 HTTP 状态码。
Slot（槽位）页面中一个具名位置，由某个片段填充。声明在 apps/<page>/src/manifest.slots.json。现有 19 个。
Minimum deployable unit就是片段。由 pnpm verify:unit --name <fragment> 予以证明。
Unit（发布工具语境）affected 图中的一个节点：route、page、component、data source 或 slice。用 pnpm graph 查询。

最容易搞混的两对

dependsOn vs dataDependencies

dependsOn 排的是槽位之间的先后（B 在 A 之后渲染）。dataDependencies 指的是页面数据源注册表里必须先解析完的条目。

两者喂给同一个拓扑调度器，但含义不同。而且：一个没有 dependsOn 的槽位并不因此就是静态的 —— 这正是优化器目前犯的错。

manifest 里的 dataDependencies vs subscriptions

dataDependencies 是片段服务端渲染时读一次的东西。subscriptions 是它的浏览器面板持续开着的东西。

刻意分开：order-form 在 render 时读 account，但不订阅任何东西。

运行时词汇

术语含义
Render strategy槽位如何产出：static | ttl-cache | cached-ssr | dynamic-ssr。
Release channelstable | canary | preview。槽位指定通道，注册表在每次请求时解析成具体版本和 serviceUrl。
Source id / 模板数据源用规范化字符串寻址（book.l2.BTC、positions）。带 <param> 占位符的是模板（book.l2.<symbol>），由页面在挂载时绑定。构造函数在 domains/trade-data/src/sourceIds.ts，不要手工拼 id。
Island（岛屿）在静态 SSR 标记中被水合的客户端组件。片段输出 DOM 加一段内联 JSON 快照；只有握手通过才水合。
Live panel（实时面板）岛屿的非 React 对应物：服务端渲染的面板，靠把订阅帧折叠成原地 DOM 补丁保持最新。由片段的 ./live 导出提供。
Snapshot handshake决定是否水合的检查。四种失败原因：version-mismatch、contract-hash-mismatch、invalid-snapshot、invalid-props。失败意味着SSR 标记原样保留，绝不会半挂载。
Page healthok | degraded | unhealthy。可选槽位失败是 degraded，仍返回 200；必需槽位失败是 unhealthy，网关返回 503。
Slice / channel带类型的跨片段通信主题。一个声明的发布者、一份显式订阅者名单、一份 Zod 载荷 schema。发布者和订阅者 id 是逻辑组件 id，不是片段名 —— symbol-switcher 是页面使用的 owner 身份，不是 fragments/ 下的服务。
Gate（闸门）pnpm verify 跑的 14 条命令之一（scripts/verify.mts）。闸门只有通过和失败两种结果；建议性的输出叫 finding，不会让构建失败。
