ai-first-web-frame

An SSR-first micro-frontend framework with two positions running through it: a fragment is the unit of deployment, and every boundary is a machine-checkable contract.

A page is not a build artefact. It is a composition of independently deployed HTTP services, each owning its own markup, data, performance budget and release channel. The page only names slots; the framework resolves each one into a concrete version and address on every request, runs them as a dependency graph, and degrades slot by slot when one fails.

Reading these docs locally

pnpm docs:serve           # http://localhost:4301
pnpm docs:serve --open    # and open a browser

Zero dependencies and no build step: one script wraps hand-authored HTML in the shared chrome. The figures are inline SVG painted with the page's own CSS variables, so a single file serves light theme, dark theme, English and 中文.

A note on these docs

Every factual claim here was checked against the source tree, and paths are cited so you can re-check. Where the implementation is narrower than the idea, the docs say so inline rather than in a footnote. Everything that is declared but not enforced, or documented but not true, is collected in Known limitations — a first-class page, not an appendix.

On the Chinese edition. Technical identifiers (dynamic-ssr, canary, POST /render, rule codes, field names) are deliberately left in English there. They are strings you type into a terminal; translating them only manufactures ambiguity. The same rule governs the figures, which is why one SVG serves both languages.
